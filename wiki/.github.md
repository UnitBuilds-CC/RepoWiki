# .github

> Automates continuous integration and package publishing for the documentation generator.

Contains GitHub Actions workflow definitions that orchestrate automated testing, validation, and distribution. These pipelines enforce code quality standards before merges and handle versioned releases to package registries, ensuring reliable delivery of the CLI and web tools without manual overhead.

## Files

### `.github/workflows/ci.yml`

Executes linting, type checking, and test suites on every commit and pull request. Validates that code changes maintain compatibility with the LLM parsing logic and dependency stack before integration.

### `.github/workflows/publish.yml`

Triggers on semantic version tags to build distribution artifacts and upload them to PyPI. Automates the release lifecycle, ensuring consistent packaging and immediate availability for end users.

## Key Concepts

- **Quality Gates**: Automated checks block merges that fail linting or testing, protecting the stability of the documentation generation engine and its LLM integrations.
- **Release Automation**: Tag-triggered publishing eliminates manual build steps, reduces human error, and guarantees reproducible distributions for both CLI and web interfaces.

## Internal Relationships

- `.github/workflows/ci.yml` → `.github/workflows/publish.yml`: CI serves as a mandatory quality gate; publish workflows only execute after CI passes, preventing broken or untested versions from reaching production registries.
