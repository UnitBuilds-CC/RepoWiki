# .github

> Automates testing, validation, and deployment of the documentation generator and its output.

Defines GitHub Actions workflows that enforce quality gates and automate release processes. The CI workflow executes linting, test suites, and dry-run documentation generation to verify that structured indexing and LLM prompts remain functional and cost-efficient. The publish workflow consumes validated build artifacts and deploys the generated wiki to a static hosting service, enabling zero-touch updates when new versions are tagged.

## Files

### `.github/workflows/ci.yml`

Orchestrates continuous integration by running linters, unit tests, and local documentation generation checks to catch regressions before merge.

### `.github/workflows/publish.yml`

Handles release automation by packaging generated documentation and deploying it to a static hosting platform upon tag creation or release events.

## Key Concepts

- **Pipeline Validation**: Ensures documentation generation logic remains stable and cost-effective across code changes by running tests and linting in CI.
- **Release-Driven Deployment**: Decouples development from publishing by triggering deployments only on explicit release events, preventing accidental or broken doc pushes.

## Internal Relationships

- `.github/workflows/ci.yml` → `.github/workflows/publish.yml`: CI validates the codebase and doc generation pipeline; publish depends on successful CI runs to safely deploy updated documentation artifacts.
