# export

> Converts internally analyzed wiki structures into consumable static formats like Markdown, JSON, and HTML.

The export module transforms the project's intermediate Wiki representation—generated by LLM analysis—into standardized, human-readable, and machine-parseable outputs. It supports multiple export targets to accommodate different downstream use cases such as version control storage, API distribution, or static site hosting. The module implements incremental update logic to avoid redundant writes, handles cross-link resolution, sanitizes content per format requirements, and maintains filesystem state to track modifications since the last export cycle.

## Files

### `crates/export/Cargo.toml`

Defines the Rust crate metadata and declares dependencies for serialization, regex parsing, and standard library features required by the export logic.

### `crates/export/src/html.rs`

Generates static HTML documentation from the Wiki model. Resolves internal links, converts Markdown to HTML, escapes unsafe characters, and injects content into predefined page templates.

- `export_html` (function) - Orchestrates the full HTML export pipeline, writing rendered pages to the specified output directory.
- `markdown_to_html` (function) - Parses raw Markdown strings into HTML, resolving internal page links and handling formatting directives.
- `inline_md` (function) - Processes inline Markdown snippets within larger documents, maintaining link context and formatting rules.
- `normalize_path` (function) - Standardizes file paths and link references to ensure consistent cross-page navigation.
- `html_escape` (function) - Sanitizes user-generated or LLM-produced text to prevent XSS and malformed HTML.
- `HTML_TEMPLATE` (constant) - Base HTML skeleton used for wrapping exported pages.
- `page` (constant) - Page-specific HTML template containing structural markup and placeholder injection points.

### `crates/export/src/json_export.rs`

Structures the Wiki data into a flat JSON schema compatible with external consumers. Maps nested sidebar hierarchies and page metadata into serializable DTOs.

- `JsonExport` (struct) - Root serialization container holding project metadata, page list, and sidebar tree.
- `PageEntry` (struct) - Represents an individual wiki page with its ID, title, content, parent relationship, and sort order.
- `SidebarEntry` (struct) - Models hierarchical navigation items with recursive child support.
- `export_json` (function) - Serializes the Wiki model into JSON format and writes it to the target path.
- `serialize_sidebar` (function) - Recursively flattens the sidebar item tree into a JSON-compatible vector structure.

### `crates/export/src/lib.rs`

Serves as the module facade, re-exporting public APIs from all submodules to provide a unified import surface for the rest of the application.

### `crates/export/src/markdown.rs`

Orchestrates Markdown generation with incremental write optimization. Tracks file states to skip unchanged pages, generates navigation sidebars and READMEs, and normalizes internal links for platform compatibility.

- `ExportSummary` (struct) - Tracks metrics for the export run, including pages written, kept, and removed.
- `StateFile` (struct) - Persists export metadata and per-page input hashes to enable incremental updates.
- `PageState` (struct) - Stores hash signatures of source inputs for a specific page to detect changes.
- `load_state` (function) - Reads the previous export state file from disk to determine which pages require regeneration.
- `save_state` (function) - Writes updated state and page hashes back to disk after a successful export cycle.
- `export_markdown` (function) - Main entry point for Markdown export. Iterates through pages, applies incremental checks, and writes only modified files.
- `write_if_changed` (function) - Compares new content against existing files and only performs disk I/O if the content differs.
- `sidebar_text` (function) - Generates Markdown-formatted navigation trees based on the wiki hierarchy.
- `readme_text` (function) - Constructs the project README Markdown, integrating overview data and navigation links.
- `strip_md_from_internal_links` (function) - Removes Markdown extension suffixes from internal links to ensure cross-platform compatibility.

### `crates/export/src/site.rs`

Produces a lightweight index.html fallback that acts as a central navigation hub or site loader when serving exported documentation statically.

- `INDEX_HTML` (constant) - Static HTML string defining the layout and script injection for the site loader.
- `write_site_loader` (function) - Writes the INDEX_HTML constant to the output directory, configuring the title and redirect behavior.

## Key Concepts

- **Incremental Export State**: Uses a persisted state file with content hashes to track which pages have changed, preventing redundant disk I/O and significantly speeding up repeated export runs.
- **Cross-Link Resolution**: Normalizes internal references between wiki pages across all output formats to ensure navigational integrity regardless of whether the consumer reads Markdown, HTML, or JSON.
- **Format-Specific Sanitization**: Applies context-aware transformations such as HTML entity escaping, Markdown link stripping, and JSON structuring to meet the strict syntactic requirements of each target format.
- **Template Injection**: Uses predefined HTML constants to wrap generated content, ensuring consistent document structure and styling without requiring external CSS or JavaScript dependencies.

## Internal Relationships

- `lib.rs` → `html.rs`: Re-exports public symbols from html.rs to expose HTML generation capabilities at the crate level.
- `lib.rs` → `json_export.rs`: Re-exports public symbols from json_export.rs to expose JSON serialization capabilities at the crate level.
- `lib.rs` → `markdown.rs`: Re-exports public symbols from markdown.rs to expose Markdown generation and state management at the crate level.
- `lib.rs` → `site.rs`: Re-exports public symbols from site.rs to expose site loader generation at the crate level.
- `markdown.rs` → `repowiki_wiki::Wiki`: Consumes the core Wiki data structure to iterate over pages, extract content, and build sidebar trees.
- `html.rs` → `repowiki_wiki::Wiki`: Accepts the Wiki model to render HTML pages and resolve cross-references between pages.
- `json_export.rs` → `repowiki_wiki::Wiki`: Reads the Wiki structure to serialize it into JSON-compatible entries and navigate relationships.
- `markdown.rs` → `html.rs`: Both modules handle content transformation but target different formats; markdown.rs strips link extensions while html.rs resolves them to anchors and applies HTML escaping.
